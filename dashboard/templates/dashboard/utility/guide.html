Guideline / Help

Use the AI Automation Platform

Start with a project, add documents when you need project context, then use chats or workflows to produce answers and structured outputs.

Projects Chats Documents Providers Workflows Executions Flow Control Agent Modes Interface Usage Flows
Workspace

Projects

A project is the top-level workspace for related chats, uploaded documents, workflows, and workflow executions.

  • Create projects from New Project in the sidebar or Projects page.
  • Open a project from the Projects list in the sidebar.
  • Delete a project from its project page when it is no longer needed.
Conversation

Chats

Chats live inside a project. Create them from the sidebar, open them from the project chat list, send messages from the composer, and delete them from the chat workspace.

General chat

When a project has no processed documents relevant to the question, the assistant answers from the selected LLM and conversation history only.

Project chat

When processed project documents are available, the backend retrieves matching document chunks and adds them as RAG context before asking the LLM.

Knowledge

Documents

Documents must be processed before they can provide text for chat retrieval or workflow inputs.

uploaded
The file exists, but processing has not completed.
queued
A background worker has been asked to process it.
processing
Text extraction and embedding work is in progress.
indexed
Text and embeddings are ready for chats and workflows.
failed
Processing failed. Check the error, then process again or re-upload.

Uploads are queued automatically. The Process action can queue processing again for an existing document when needed.

AI setup

Providers

Chat providers

Control future LLM responses for chats, agents, and workflow steps. Changing the chat default affects new AI calls after the setting is saved.

Embedding providers

Control how document vectors are created for retrieval. Provider, model, and dimensions matter for compatibility.

Existing document embeddings belong to the embedding provider/model used when they were created. If you change embedding defaults, rebuild or sync old document embeddings. Newly uploaded documents use the new embedding provider automatically.

The Providers page shows active defaults, available providers, saved-key state, health checks, and rebuild/sync tools when supported by the backend.

Automation

Workflows

A workflow is an ordered set of AI steps. Each step has a name, order, prompt template, and optional dependencies. Dependencies pass previous step outputs into later prompts.

Inputs and outputs

A run starts with user input or selected document text. Each step produces output; the final run stores raw input, raw output, events, and any structured result the frontend can parse.

Builder

Create custom workflows, add steps, edit prompt text, set dependencies, then run the workflow from the Workflows page.

Results

Executions

Workflow runs use statuses such as pending, running, completed, failed, paused, and canceled. Pending is the queued state shown before a worker starts the run.

  • The Executions page lists workflow runs and keeps active statuses updated.
  • The Execution Details page shows structured output when available.
  • Raw input, raw output, and events are available in expandable sections for debugging.
  • Workflow runs are background jobs, so you can navigate to other pages while a run continues.
Flow Control

Stop, Resume, and Retry

Lifecycle and status badges

Executions / Logs shows Workflow runs across projects. Status badges update while runs are pending or running, then stop polling once a terminal state appears. Open Execution # to see the status, structured result, event count, Run input, Run output, and Events.

Execution timeline

The current timeline is the expandable Events list on the Execution Details page. Events show event type, timestamp, and raw payload, which is the main place to inspect progress updates, error information, and debugging details.

Stop appears for pending or running executions. It requests cancellation, marks the run as canceled in the backend, and attempts to revoke the background worker task. Cancellation is best-effort for work already in progress; the final status appears in the execution badge and Execution Details. Navigating away does not stop a background execution.

Retry appears for completed, failed, paused, canceled, or cancelled executions. It starts a new execution using the same workflow and original run input, then redirects to the new Execution Details page when the backend returns the new run. Retry differs from Resume because it creates a fresh run rather than continuing the existing one.

Resume appears for failed, paused, canceled, or cancelled executions. It asks the backend to continue the same execution from the run state it can recover, including already completed workflow steps where the backend has them. Progress and final results appear on the same execution record.

Chats create conversation messages. Workflows create workflow executions. Workspace Agent can inspect and queue workflow-related operations from chat, but execution history is monitored from Executions / Logs.

AI Assistants

Agent Modes

Chat Assistant

Chat Assistant is the general-purpose assistant for everyday questions and writing help. Use it for explanations, editing, translation, brainstorming, coding questions, and follow-up questions that rely on conversation history. It does not perform platform automation such as creating workflows or rebuilding embeddings.

  • Explain how JWT authentication works.
  • Improve this email.
  • Translate this paragraph into French.
  • Write a PostgreSQL query to find duplicate users.
  • Explain Docker networking.

Project Assistant

Project Assistant specializes in the current project and uses uploaded, processed project documents as context when relevant. Use it to summarize, compare, and explain project content, or to answer questions grounded in project files. It can answer from project context, but it does not change platform resources.

  • Summarize the uploaded contract.
  • What are the main project requirements?
  • Compare these two specifications.
  • Which documents mention PostgreSQL?
  • Explain the deployment process described in the uploaded documentation.

Research Agent

Research Agent is the analysis-focused AI for the active workspace/project. Select it from the Agent mode dropdown in the chat composer; it uses the active project context and uploaded project documents to perform deeper investigations. It can compare multiple documents, identify risks, extract requirements, detect inconsistencies, build structured summaries, and synthesize information across different sources. It focuses on analysis and evidence gathering rather than executing platform operations or modifying workspace resources.

  • Identify the main project risks.
  • Compare all uploaded requirements documents.
  • Create a stakeholder summary.
  • Find conflicting requirements.
  • Produce a structured project overview.

Workspace Agent

Workspace Agent is the operational AI for the active workspace/project. Select it from the Agent mode dropdown in the chat composer; it uses the active project context and may use uploaded project documents. It can inspect documents and workflows, check embedding rebuild needs, process documents, rebuild or sync embeddings, create or modify workflows, run workflows, inspect execution history, and diagnose failed executions. Long-running actions use background execution, and it cannot operate outside resources owned by the current user.

  • Check which documents need embedding rebuild.
  • Update files to use the current embedding model.
  • Create a workflow that extracts invoice information.
  • Run the contract review workflow on contract.pdf.
  • Explain why the latest workflow execution failed.
Interface

UI / hidden interactions

  1. The sidebar can be opened, closed, and resized on desktop. The collapsed state and width are saved in your browser.
  2. When the sidebar is closed on desktop, move the pointer to the left edge of the viewport to temporarily reveal it. It remains visible while you interact with it, then hides again after the pointer leaves. On screens 980px wide or smaller, the top sidebar has a scrollbar so you can see more content below.
  3. Many pages use expandable blocks. When you see an arrow, chevron, disclosure icon, or expand icon, open it to reveal details such as workflow templates, steps, events, logs, raw input, or raw output.
