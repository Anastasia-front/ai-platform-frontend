Guideline / Help

Use the AI Automation Platform

Start with a project, add documents when you need project context, then use chats or workflows to produce answers and structured outputs.

Projects Chats Documents Providers Workflows Executions Interface Usage flows
Workspace

Projects

A project is the top-level workspace for related chats, uploaded documents, workflows, and workflow executions.

  • Create projects from New Project in the sidebar or Projects page.
  • Open a project from the Projects list in the sidebar.
  • Delete a project from its project page when it is no longer needed.
Conversation

Chats

Chats live inside a project. Create them from the sidebar, open them from the project chat list, send messages from the composer, and delete them from the chat workspace.

General chat

When a project has no processed documents relevant to the question, the assistant answers from the selected LLM and conversation history only.

Project chat

When processed project documents are available, the backend retrieves matching document chunks and adds them as RAG context before asking the LLM.

Knowledge

Documents

Documents must be processed before they can provide text for chat retrieval or workflow inputs.

uploaded
The file exists, but processing has not completed.
queued
A background worker has been asked to process it.
processing
Text extraction and embedding work is in progress.
indexed
Text and embeddings are ready for chats and workflows.
failed
Processing failed. Check the error, then process again or re-upload.

Uploads are queued automatically. The Process action can queue processing again for an existing document when needed.

AI setup

Providers

Chat providers

Control future LLM responses for chats, agents, and workflow steps. Changing the chat default affects new AI calls after the setting is saved.

Embedding providers

Control how document vectors are created for retrieval. Provider, model, and dimensions matter for compatibility.

Existing document embeddings belong to the embedding provider/model used when they were created. If you change embedding defaults, rebuild or sync old document embeddings. Newly uploaded documents use the new embedding provider automatically.

The Providers page shows active defaults, available providers, saved-key state, health checks, and rebuild/sync tools when supported by the backend.

Automation

Workflows

A workflow is an ordered set of AI steps. Each step has a name, order, prompt template, and optional dependencies. Dependencies pass previous step outputs into later prompts.

Inputs and outputs

A run starts with user input or selected document text. Each step produces output; the final run stores raw input, raw output, events, and any structured result the frontend can parse.

Builder

Create custom workflows, add steps, edit prompt text, set dependencies, then run the workflow from the Workflows page.

Results

Executions

Workflow runs use statuses: pending, running, completed, failed, and paused.

  • The Executions page lists workflow runs and keeps active statuses updated.
  • The Execution Details page shows structured output when available.
  • Raw input, raw output, and events are available in expandable sections for debugging.
  • Workflow runs are background jobs, so you can navigate to other pages while a run continues.
Interface

Sidebar and expandable sections

  1. The sidebar can be opened, closed, and resized on desktop. The collapsed state and width are saved in your browser.
  2. When the sidebar is closed on desktop, move the pointer to the left edge of the viewport to temporarily reveal it. It remains visible while you interact with it, then hides again after the pointer leaves.
  3. Many pages use expandable blocks. When you see an arrow, chevron, disclosure icon, or expand icon, open it to reveal details such as workflow templates, steps, events, logs, raw input, or raw output.
